# Brick Breaker Plus

This is a larger Brick Breaker example written fully in Crustini source.

It uses a `320x240` screen, 18 bricks, lives, win/loss states, mouse control, keyboard control, and the crude helper verbs that lower to Rust runtime functions.

## Authored Files

```txt
examples/brick-breaker-plus/
  app.flour
  README.md
```

Everything under `.bakery/` is generated by `rx`. Do not edit it as source.

## Run It

From the repo root:

```bash
cargo run --bin rx -- examples/brick-breaker-plus/app.flour
```

Once `rx` is installed:

```bash
rx examples/brick-breaker-plus/app.flour
```

Controls:

- Left/right arrows move the paddle.
- Mouse click also starts the game and moves the paddle.
- `A` or `Start` starts the game.
- `Esc` quits the native preview window.

## What Gets Compiled

`app.flour` contains:

```txt
screen!(320, 240)
fps!(50)
state! { paddle, ball, mode, lives, score, flash, bricks }
update! { input, movement, clamp!, hit_rect!, abs!, win/loss }
draw! { background, header, lives, bricks, walls, paddle, ball, text }
```

Layer 1 is the language compiler:

```bash
cargo run --bin rx -- emit examples/brick-breaker-plus/app.flour
```

That command reads the authored `.flour` file and lowers it into Rust that implements `crustini_core::CrustiniApp`.

The generated Rust app crate is written here when you run or bake:

- `.bakery/src/lib.rs`
- `.bakery/Cargo.toml`

That generated crate contains:

- `WIDTH`, `HEIGHT`, and `FPS`
- an `App` struct with the `state!` fields
- `App::new()`
- `impl CrustiniApp for App`
- Rust methods for `setup`, `update`, and `draw`

Concrete examples:

```rust
screen!(320, 240)
fps!(50)
```

compiles to:

```rust
pub const WIDTH: usize = 320;
pub const HEIGHT: usize = 240;
pub const FPS: usize = 50;
```

This source:

```rust
paddle_x = clamp!(paddle_x, 8, 260)
```

compiles to:

```rust
self.paddle_x = crustini_core::clamp_i16(self.paddle_x, 8, 260);
```

This source:

```rust
if hit_rect!(ball_x - 3, ball_y - 3, 6, 6, paddle_x, 202, 52, 7) {
  ball_vy = 0 - abs!(ball_vy)
}
```

compiles to:

```rust
if crustini_core::hit_rect(self.ball_x - 3, self.ball_y - 3, 6, 6, self.paddle_x, 202, 52, 7) {
    self.ball_vy = 0 - crustini_core::abs_i16(self.ball_vy);
}
```

This source:

```rust
rect!(paddle_x, 202, 52, 7, 245)
circle!(ball_x, ball_y, 4, 255)
```

compiles to:

```rust
screen.rect(self.paddle_x, 202, 52, 7, 245);
screen.circle(self.ball_x, self.ball_y, 4, 255);
```

Layer 2 is the host/binary layer:

```bash
cargo run --bin rx -- bake examples/brick-breaker-plus/app.flour
```

`rx bake` compiles the generated Rust app crate into an artifact. For file-shaped examples, that artifact is the generated app library:

- `.bakery/target/debug/libcrustini_generated_brick_breaker_plus.rlib`

When you run the bare path, `rx` adds the native preview shell:

```bash
cargo run --bin rx -- examples/brick-breaker-plus/app.flour
```

That writes:

- `.bakery/preview/Cargo.toml`
- `.bakery/preview/src/main.rs`

The preview crate depends on:

- the generated app crate in `.bakery/`
- `crustini-core`
- `crustini-host`

Then Cargo builds and runs the preview crate. `crustini-host` owns the minifb native window; the language compiler does not know about windows.

## Authored Source Versus Generated Files

Authored source:

- `app.flour`
- `README.md`

Generated by `rx`:

- `.bakery/src/lib.rs`
- `.bakery/Cargo.toml`
- `.bakery/preview/src/main.rs`
- `.bakery/preview/Cargo.toml`
- `.bakery/target/`
- `.bakery/preview/target/`

This split is the shape we want: users write `.flour`, the compiler emits a tiny Rust app, and the preview shell stays outside the language.
